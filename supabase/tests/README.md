# SQL / RLS / RPC тесты

Эти тесты проверяют самую рискованную часть проекта — права доступа
(Row Level Security) и серверную логику (RPC-функции) — против настоящего
PostgreSQL, а не только чтением кода. Именно так в процессе разработки
были найдены реальные баги: неправильная нормализация номеров телефона и
утечка списка сотрудников анонимным посетителям через view.

Это **не** тесты фронтенда — для них смотрите `npm run test` в корне
проекта. Это дополнительная сетка безопасности для самой БД.

## Запуск

Нужен локальный PostgreSQL (не обязательно полный Supabase — просто
Postgres 15+; например `apt install postgresql` на Ubuntu/Debian).

```bash
./supabase/tests/run.sh
```

По умолчанию скрипт подключается через `su - postgres -c "psql ..."`
(так настроен пользователь `postgres` в этой среде разработки). Если у
вас локальный Postgres настроен иначе, переопределите:

```bash
PSQL_RUN='psql -U postgres -h localhost -c' TEST_DB=my_test_db ./supabase/tests/run.sh
```

Скрипт **пересоздаёт** базу `restaurant_test` с нуля при каждом запуске —
не указывайте настоящую базу.

### Тест на реальный race condition (гонка данных)

Проверка «два сотрудника одновременно нажали „Я выйду“» требует
настоящих параллельных процессов, поэтому она вынесена отдельно:

```bash
./supabase/tests/run.sh   # сначала применит миграции
./supabase/tests/race_condition_concurrent_accept.sh
```

## Что проверяется (файлы по порядку)

| Файл | Что проверяет |
|---|---|
| `01_employees_admin_rls.sql` | Регистрация, привязка по телефону (включая формат 8 vs +7), кто что видит |
| `02_shifts_requirements.sql` | Смены сотрудников, границы времени, потребности |
| `03_shortage_priority_queue.sql` | Обнаружение дефицита, «Пропустить», очередь запросов, приоритет посудомойщика |
| `04_push_subscriptions.sql` | Изоляция push-подписок по владельцу |
| `05_attendance_admin_conflicts.sql` | Приход/уход, редактирование админом, обнаружение пересечений |
| `06_admin_attendance_insert.sql` | Прямая вставка фактического времени админом (когда сотрудник забыл отметиться) |
| `07_early_late_arrival.sql` | Приход раньше/позже плана сохраняется без округления |
| `race_condition_concurrent_accept.sh` | Настоящая гонка: 6 параллельных подключений, needed_count=2 |
